# 1. 연구 목표·범위·현재 상태

연구의 중심을 고정한다


**최종 목표는 자연스럽게 편곡된 실제 음악에서 정확도가 높은 악기별 독립 전문가를 만들고, 통합 시스템의 다중악기 채보 성능을 같은 조건의 강한 공개 기준보다 높이는 것이다.**


각 악기 모델은 독립 가중치와 독립 학습 목적을 갖는다. 동일 음원을 각 전문가에게 직접 줄 수 있으며, 음원 분리는 선택적 입력 경로다. MoE 구축이나 하나의 공유 backbone으로 대체하는 것은 본 연구의 주 경로가 아니다. [S1]


## 이 문서의 “모든 경우의 수”


지금까지 논의한 가설을 15개 연구축, 120개 후속 실험 카드로 등록하고 첫 실험 1개와 사전 검증 12개를 따로 정의했다. 타깃·반주 음악성, 자료 출처, 모델 구조, 학습법, 입력, 손실, 규모, 결과 판정을 교차할 수 있는 설계 공간도 명시했다. 무한한 수치 조합을 전부 실행하겠다는 뜻이 아니라, 정한 축의 선택지와 결과별 다음 행동을 빠뜨리지 않는 설계다.


| 구분 | 의미와 취급 |
| --- | --- |
| 확정 방향 | 정상 실제음악 우선, 독립 전문가, MuScriptor 기반 Bass pilot, M0/C1/M1/M2, AWS 보유 크레딧 $100 한도. |
| 계획값 | 5초 입력, 1-seed screening, 3,000-step 시작안, TPCR 50% 교체 등은 pilot 조건이며 측정 뒤 잠근다. |
| 제안 | 후속 실험 카드·새 대조군·결과별 분기·논문 묶음은 실행 전 설계안이다. |
| 미확인 | 학습 완료·성능 향상·실험별 소요시간·현재 계정 GPU 접근 권한·신규성의 완전한 확인은 제시된 자료로 입증되지 않았다. |



## 원자료와 정교화 제안의 구분


기존 대화는 [S1], 업로드한 상세 검토문은 [S2], 제공된 실행 README는 [S3]으로 구분한다. 본문에서 “방법론 정교화”로 표시한 부분은 기존 자료의 문구를 그대로 반복하지 않고 추가 통제와 해석 제한을 제안한 것이다. 120개 카드는 확정 사실이 아니라 검증할 초안이다.


> “정상 실제음악”과 “학습분포 내부(ID)”는 동의어가 아니다. 처음 보는 장르도 정상 음악일 수 있다. “SOTA”는 벤치마크·악기 범위·허용 정보·평가지표를 정했을 때만 판단한다.

# 2. 전체 진행 트리

하나의 본선과 여러 연구 가지


```text
[최종 목표] 정상 실제음악의 다중악기 채보 성능 향상
  │
  ├─ P0  검증 토대: G00–G11
  │    ├─ 데이터: 정답 음높이·정렬·중복·사용권
  │    ├─ 코드: 토큰·경계·손실·평가·재개
  │    └─ 비용: 모델별 100-step + 실제 생성 속도
  │
  └─ P1  EXP01: 독립 Bass Specialist pilot
       ├─ M0: 원본
       ├─ C1: 전체 악기 추가학습
       ├─ M1: 베이스만 추가학습
       ├─ M2: 베이스 + TPCR 50% 교체
       └─ 네 조건 비교 결과로 후속 가지 선택
            ├─ S / F  전문화·파인튜닝·망각
            ├─ C / R  반주 교체·무규칙 MIDI
            ├─ I      같은 타깃의 일관성 학습
            ├─ D / A  실제 정답·합성 렌더·그루브
            ├─ P / V  FFT·배음·F0·음원 분리
            └─ X      드럼·베이스의 명시적 정보 전달
                    │
                    └─ 악기별로 재현 → 규모 확대(K)
                          │
                          ├─ Q  신뢰도·오류 감지
                          ├─ B  독립 모델 묶음·통합
                          └─ E  공통 평가·통계·재현성
                                │
                                └─ Z  전체 SOTA 검증
                                      ├─ 악보 변환
                                      ├─ 표현 정보
                                      └─ 효율·실시간·배포
```


P0는 필수 기반, P1은 첫 실험과 바로 필요한 후속, P2는 효과가 보일 때 확장할 방법론, P3는 충분한 자료·모델·연산을 확보한 뒤의 통합 단계다. 모든 가지를 순서대로 완주할 필요는 없다. 다음 한 번의 실험은 가장 큰 불확실성 하나를 줄이는 쪽으로 고른다.


> 트리의 모든 화살표는 연구 의존관계다. 자동으로 성능이 좋아진다는 뜻이 아니며, 비용과 기간은 실측 전 확정하지 않는다.

# 3. 첫 실험 다음의 행동 트리

성공·실패·불확정을 모두 남긴다


```text
EXP01 실행 전
  ├─ 데이터/코드 검증 실패 → G 단계 수정 → 재검증
  ├─ 검증 미완료           → 작은 검증만 수행
  └─ 검증 통과            → C1/M1/M2 1-seed screening
                               │
                  실제음악 결과가 있는가?
                  ├─ 없음 → 결과를 합성음 pilot로 한정
                  │        → 실제음악 평가 자료 확보(D/E)
                  └─ 있음
                       │
            M1이 C1보다 유리한가?
            ├─ 개선 → 다른 seed/크기/악기 재현(S/K)
            ├─ 동등 → 추가학습 효과·타깃 비중 점검(S06)
            ├─ 악화 → 망각·도메인·갱신 범위 점검(F/D)
            └─ 불확정 → 표본·반복·측정 정밀도 보강(E05)
                       │
            M2가 M1보다 유리한가?
            ├─ 실제음악 개선 → TPCR 비율·대조군(C01/C02)
            │                   └─ 기전은 별도 진단(C/I)
            ├─ robustness만 개선 → 보조 성과, 본선은 성능 개선
            ├─ 실제음악 악화 → 비율 축소·정상자료 복습(F05)
            └─ 불확정/무효 → 확인 실험 또는 다른 가지(P/V/D)
```


## 효과가 없어도 전체 아이디어를 폐기하지 않는다


M1이 나빠졌다는 결과는 “이번 MuScriptor-small + Slakh-only + 선택한 갱신/학습률 조합이 실패했다”는 뜻이다. 독립 전문가 전체 방향이 틀렸다고 할 수 없다. 반대로 베이스가 좋아졌다는 사실만으로 모든 악기나 전체 통합 SOTA를 입증할 수도 없다. [S2 §13,31]


## 교수 상담 시점


첫 결과가 있으면 연구 질문 1장, 대조군 표, 실제/합성 분리 결과, 데이터 감사 요약, 다음 비교 1개와 실측 GPU 예산을 들고 상담한다. 가설이 맞아야만 상담할 수 있는 것은 아니다. 데이터·trainer가 막혔을 때도 정확히 어느 검증에서 실패했는지 보여주면 된다.

# 4. EXP01의 공식 정의

MuScriptor 기반 독립 Bass Specialist 및 TPCR 효과 검증


질문은 ① 추가학습의 실용적 이득, ② 전체 악기 추가학습 대비 베이스 전용 목적의 이득, ③ 정해진 타깃 노출 예산에서 TPCR 교체의 이득이다. 초기 체크포인트의 정확한 revision/hash를 고정하며 M2도 M1에서 이어서가 아니라 같은 원본에서 시작한다. [S2 §23–26]


| 조건 | 학습 입력 → 정답 | 역할 |
| --- | --- | --- |
| M0 | 학습 없음; 평가에서 Bass 조건 요청 | 공개 원본 기준 |
| C1 | 원곡 혼합음 → 전체 악기 MIDI | 일반 추가학습 대조 |
| M1 | 같은 원곡 혼합음 → Bass MIDI | 독립 베이스 전문화 |
| M2 | 같은 타깃, 정상/TPCR 50:50 → Bass MIDI | 반주 교체 효과 |
| M1-R (후속) | 원곡 반복/리믹스 → Bass MIDI | 일반 증강 효과 대조 |



| 비교 | 허용되는 해석 |
| --- | --- |
| C1 − M0 | 일반적인 추가학습 recipe의 이득 |
| M1 − M0 | 베이스 전문화 recipe 전체의 실용적 이득 |
| M1 − C1 | 동일 음원 노출 조건에서 베이스 전용 학습 목적의 상대적 이득 |
| M2 − M1 | 같은 타깃 노출 조건에서 TPCR replacement 이득 |
| M2 − M1-R | 일반 반복/리믹스보다 반주 교체가 주는 추가 이득 |



## 방법론 정교화: 같은 step 수는 같은 연산량이 아니다


C1의 전체 악기 정답은 M1보다 긴 토큰열일 수 있다. 따라서 같은 음원·batch·업데이트 수를 써도 GPU시간/FLOPs가 달라질 수 있다. EXP01의 주 비교는 “동일 음원 및 타깃 노출”로 부르고, 실제 연산량을 따로 보고한다. 고정 GPU시간 비교는 K03/B08의 보조 실험으로 분리한다.


또한 C1과 M1의 요청 악기 조건·타깃 가중치가 다르면 그 효과도 섞일 수 있다. S06의 부분집합 요청/타깃 비중 대조가 전문화 기전을 더 좁혀준다. EXP01만으로 “독립 네트워크라는 사실 자체의 인과적 우월성”을 주장하지 않는다.

## 모든 검증 결과는 파일로 남긴다


PASS / FAIL / PENDING 중 하나를 부여한다. 증빙 경로, 검사한 데이터/코드 hash, 표본 수, 허용오차, 검토자, 시점을 기록한다. FAIL이면 해당 경로의 본 학습을 멈추고, PENDING이면 그 부분이 필요한 주장을 하지 않는다. 이미 통과한 독립적인 로컬 검증은 계속 진행할 수 있다.


G00–G05는 가능한 한 로컬 CPU에서 처리한다. G09–G11에는 제한된 GPU 검증을 사용할 수 있다. “모든 감사 전 GPU 사용 금지”가 아니라, 검증되지 않은 자료로 대규모 본 학습을 하지 않는다는 원칙이다. [S2 §27; 방법론 정교화]


> 32-sample 생성 Onset F1≥0.98·Offset F1≥0.95는 구현 점검용 목표값이지 보편적 합격 규정은 아니다. 표본의 표현 가능성·경계 scoring·짧은 학습 예산을 먼저 확인하며, 미달 자체를 연구 가설 반증으로 보지 않는다.

## 모든 검증 결과는 파일로 남긴다


PASS / FAIL / PENDING 중 하나를 부여한다. 증빙 경로, 검사한 데이터/코드 hash, 표본 수, 허용오차, 검토자, 시점을 기록한다. FAIL이면 해당 경로의 본 학습을 멈추고, PENDING이면 그 부분이 필요한 주장을 하지 않는다. 이미 통과한 독립적인 로컬 검증은 계속 진행할 수 있다.


G00–G05는 가능한 한 로컬 CPU에서 처리한다. G09–G11에는 제한된 GPU 검증을 사용할 수 있다. “모든 감사 전 GPU 사용 금지”가 아니라, 검증되지 않은 자료로 대규모 본 학습을 하지 않는다는 원칙이다. [S2 §27; 방법론 정교화]
